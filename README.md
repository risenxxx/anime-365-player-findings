# Сбои веб‑плеера Anime 365: проблемы и предлагаемые решения

Сборник проблем веб‑плеера Anime 365 — бесконечные перезагрузки, прыжки в начало
серии, зависания потока — с причинами в коде и предлагаемыми решениями. Каждая проблема
подтверждена воспроизведением. Для подтверждённых есть небольшой патч, проверенный тем же сценарием до и после.

- **[SOLUTIONS.md](SOLUTIONS.md)** — предлагаемые решения: что происходит, почему и как
  исправить в исходниках (с эскизами кода).
- **[REPORT.md](REPORT.md)** — доказательная база: где в коде, как воспроизвести, что
  показали логи, результат с патчем.
- **[patches/](patches/README.md)** — минимальные патчи к текущему коду, проверенные на
  стенде.

## Проблемы и решения

Последняя проверка — **27.10.2026**, на коде сайта после исправлений (`concatenate?1793007100`,
`swMain.js?v=27`): все сценарии на локальном стенде и живая запись на проде. Подробности —
[REPORT.md, «Проверка после исправлений сайта»](REPORT.md#проверка-после-исправлений-сайта-27102026).

Проверено и **не воспроизводится** в Chrome 155: остановка SW на 5‑й минуте долгого
fetch‑события (H6) и обрыв просмотра при деплое новой версии SW (H7). Подробности — в
[REPORT.md](REPORT.md).

**Насколько это заметно.** На живых записях с быстрым соединением (24.10 и 27.10) сбоев не было: SW скачал
всю серию в кэш примерно за 28 с, и дальше всё шло из кэша. Эти проблемы касаются прежде
всего медленных и нестабильных соединений, долгих сессий (истекающие подписи), подмены
файлов на CDN и браузеров, где SW не работает. Долю таких просмотров покажет
телеметрия сайта (`videoTelemetry`: `err`, `rb`).

## Как это проверялось

- **Локальный стенд:** скачанный код сайта (по манифесту с sha256, в репозиторий не
  кладётся), локальный CDN со сбоями на отдельном origin, синтетическое видео, настоящий
  Chrome под управлением по CDP. DevTools к воркеру не подключались.
- **Живая проверка:** обычный просмотр одной серии в одной вкладке, NetLog без тел; сбои —
  только в собственный трафик через локальный mitmproxy. В репозитории только
  отредактированные выжимки.
- Все выводы — для Chrome 155 на macOS. Safari — ручной чек‑лист в REPORT.md.

Ниже — правила, по которым собирались данные, и как запустить всё локально.

## Правила сбора данных

1. **Никаких прямых ссылок на видео и никакого их извлечения.** Обфусцированный
   `data:`‑скрипт embed‑страницы, который подставляет источники, не декодируется и не
   запускается: локальная сборка embed его выбрасывает (`scripts/build-embed.mjs`).
   Файлы серий не скачиваются. На настоящих сериях работа идёт только через обычный
   просмотр в браузере.
2. **Сырые записи трафика не попадают в git.** NetLog/HAR/дампы mitmproxy лежат только в
   `captures/raw/` (игнорируется). В репозиторий идут только выжимки, прошедшие через
   `scripts/redact.mjs`: хосты CDN заменены на `cdn-1`, `cdn-2`…, query‑строки и токены
   удалены, cookies/`Set-Cookie`/csrf/IP вырезаны, значение `m` заменено на `m-A`, `m-B`…
3. **Код сайта не вендорится.** `scripts/fetch-site.mjs` скачивает файлы в `vendor/site/`
   (игнорируется) и сверяет sha256 с `vendor-manifest.json`. Если хэш не сошёлся, скрипт
   ничего не перезаписывает и сообщает об изменении. Исправления — маленькие `.patch`
   в `patches/`.
4. **Ничего личного в коммитах.** Перед коммитом хук запускает
   `node scripts/redact.mjs --check` (URL CDN, подписи, cookies, IP, пути `$HOME`, e‑mail,
   имя пользователя/машины). Если проверка падает, коммита нет.
5. **Звук выключается в самом плеере** (`muted`, громкость video.js = 0). Системная
   громкость не трогается.
6. **Их CDN не нагружается.** Живые прогоны идут последовательно, в одной вкладке, с
   паузами. Сбои впрыскиваются только в собственный трафик через локальный прокси, число
   попыток всегда ограничено.
7. Вход в аккаунт (если нужен) выполняется вручную в отдельном профиле Chrome в
   `profiles/` (игнорируется). Пароли и cookies в репозиторий не попадают.

## Как запустить локальный стенд

Нужны macOS, Google Chrome (именно Chrome: в Chromium из Playwright нет H.264; проверялось
на 155.0.8059.85), Node 20, ffmpeg с `libx264` и `aac`.

```sh
npm install
npm run hooks                 # pre-commit: redact --check
npm run fetch-site            # vendor/site/ + проверка sha256
npm run pretty                # vendor/pretty/ — разметка как у `js-beautify -s 2`
npm run media                 # media/episode.mp4 и media/twin.mp4 (~300 МБ каждый)
npm run test:quick            # все сценарии, кроме долгих H6 (~35 мин)
npm run test:all              # все сценарии (~50 мин)
node runner/run.mjs h4-expired-403-sw      # один сценарий
node runner/run.mjs --patched=all h4-expired-403-sw   # тот же сценарий с патчами
```

Результат — `results/<дата>/summary.md` и по файлу на сценарий. Сырые логи прогона
(события страницы, строки SW, журнал CDN) — в `results/<дата>/raw/` (игнорируется),
NetLog — в `captures/raw/`.

### Живая проверка (нужен вход в аккаунт)

```sh
node runner/live.mjs login                       # вход вручную в тестовом профиле profiles/live
node runner/live.mjs baseline <url серии>        # ~10 мин, без прокси, NetLog
brew install mitmproxy
mitmdump -s proxy/faults.py --set stream_large_bodies=1 --set faults_config=captures/raw/faults.json \
  --set flow_detail=0 --ignore-hosts '<сайт, вход, служебные хосты>' --listen-host 127.0.0.1 --listen-port 8080
node runner/live.mjs proxy <url серии> --spki=<SPKI-хэш CA mitmproxy>
node scripts/netlog-summary.mjs captures/raw/live-<ts>.netlog   # выход уже отредактирован
```

Пример конфига сбоев — `proxy/faults.example.json`. mitmproxy вскрывает только хосты CDN:
страница сайта и вход (VK) идут с настоящими сертификатами. Если подменить сертификат
страницы, Chrome отказывает ей в API Service Worker. Доверие к CA mitmproxy действует только
на время запуска (`--ignore-certificate-errors-spki-list`), системная связка ключей не
меняется. Перед прогоном со сбоями нужно очистить Cache Storage и HTTP‑кэш тестового
профиля, иначе серия играет из кэша и до CDN не доходит.

### Устройство

| часть | что делает |
|---|---|
| `server/site` | `http://localhost:8301`: embed, собранный из скачанной копии, и все скрипты по тем же путям, включая `/sworker.js?24` и `/swMain.js?v=24`. К `sworker.js` спереди добавлена тонкая обёртка `sw-log-wrapper.js`: она пересылает `console.log/error` воркера на локальный сборщик. Логика `swMain.js` не меняется. Эндпоинты `brokenVideo`, `watched`, `videoTelemetry`, `sources` — заглушки с журналом. |
| `server/cdn` | `http://127.0.0.1:8302` — другой origin. Range/206, CORS с настраиваемым `Expose-Headers`, ограничение скорости, лимит соединений, сбои: обрыв через N байт или по команде, статусы 403/429/5xx (с CORS и без), порча байтов, другой файл под тем же `m`. Журнал каждого запроса: Range, `Sec-Fetch-Dest` (`video` — сам `<video>`, `empty` — `fetch()` из SW), статус, сколько байт отдано, почему закрыт. |
| `runner/` | голый CDP через `ws`. Запускает Chrome с временным профилем, `--autoplay-policy=no-user-gesture-required` и `--log-net-log`, подключается **только к странице** (без `Target.setAutoAttach`: DevTools на воркере отменяет его остановку по таймауту, см. H6). Воркеры только наблюдаются через `Target.setDiscoverTargets`. `probe.js` пишет события `<video>`, вызовы `load()`/`src`, `currentTime` раз в секунду. `detectors.mjs` считает ошибки, перезагрузки за минуту, прыжки назад, сброс в начало после ошибки, цикл ошибок без `notifyBroken`. |
| `runner/scenarios/` | по файлу на сценарий: условия, шаги, ожидаемый результат и правило вердикта |
| `scripts/` | `fetch-site`, `pretty`, `build-embed`, `make-media`, `netlog-summary`, `redact` |
| `proxy/faults.py` | дополнение mitmproxy для впрыска сбоев в собственный живой трафик |
| `patches/` | исправления против prettified‑версии и описание переноса в исходник |

Чем локальная embed‑страница отличается от настоящей (`scripts/build-embed.mjs`): нет
обфусцированного скрипта и его удалителя, плагина seed и внешних загрузчиков,
счётчиков, промо‑оверлея и синхронизации cookies. Субтитры выключены, OneSignal заменён
пустой заглушкой (push‑уведомления к плееру не относятся). `data-require-activation="0"`,
источники — свои. Остальные скрипты плеера и SW — байт в байт как на сайте.

Ограничения стенда: локальный CDN работает по HTTP/1.1 (на проде h2/QUIC); Safari
проверяется вручную (чек‑лист в REPORT.md).

## English summary

A catalogue of playback problems in the Anime 365 web player (endless reloads,
jumps to the start of an episode, stalled streams), with root causes in the code and
proposed fixes, written for the site's developers. See [SOLUTIONS.md](SOLUTIONS.md) for the
fixes, [REPORT.md](REPORT.md) for the evidence and [patches/](patches/README.md) for
minimal patches verified before/after. Everything was reproduced on a local bench: the
site's code is downloaded (not vendored) and verified by sha256, the obfuscated
source‑injecting script is dropped and never decoded, media is synthetic, a fault‑injecting
CDN runs on a separate origin, and real Chrome is driven over raw CDP attached to the page
only. Live checks used ordinary viewing in one tab; only redacted summaries are committed.
